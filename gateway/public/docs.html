API Gateway Documentation

A production-grade reverse proxy gateway with JWT authentication, Redis-backed rate limiting, circuit breaker resilience, and role-based access control.

Node.js Express Redis Cloud JWT Opossum Docker MongoDB
ⓘ All protected routes require a valid AccessToken cookie. Login first to receive tokens. Admin routes additionally require the role: "admin" claim in your JWT.
Gateway
GET /health Check health of all downstream services public ▶
Description

Pings all three microservices in parallel and returns their health status. Returns 200 if all healthy, 503 if any service is down.

Response — 200 OK
{
  "gateway": {
    "status": "healthy",
    "healthy": true,
    "uptime": 3612.4
  },
  "services": {
    "auth": { "status": "healthy", "healthy": true, "circuit": "closed" },
    "user": { "status": "healthy", "healthy": true, "circuit": "closed" },
    "product": { "status": "healthy", "healthy": true, "circuit": "closed" }
  }
}
Responses
200
All services healthy
503
One or more services unreachable

POST /logout Revoke refresh token and clear session auth ▶
Description

Blacklists the RefreshToken in Redis (7 day TTL) and clears both cookies. Even if someone has a stolen RefreshToken, it cannot be used after logout.

Responses
200
Logged out. Both cookies cleared, token blacklisted in Redis.
401
No RefreshToken cookie found
Try it out

Users
GET /users/profile Fetch the authenticated user's profile auth ▶
Description

Extracts the user ID from the verified JWT and fetches the profile from the User Service. The gateway injects x-user-id and x-user-email headers — the client never touches these.

Response — 200 OK
{
  "user": {
    "_id": "6a265e9e4fa38d9ee8897b91",
    "Email": "user@example.com",
    "name": "user",
    "phone": "2353294254",
    "role": "user",
    "createdAt": "2025-06-01T10:00:00.000Z"
  }
}
Responses
200
User profile (password excluded)
401
No token / expired token
404
User not found
503
User service unavailable (circuit open)
Try it out

Admin
GET /admin/users List all registered users admin only ▶
Description

Returns all users from the database. Requires role: "admin" in JWT payload. The gateway enforces this at the routing layer and the User Service double-checks via the x-role header.

Response — 200 OK
{
  "users": [
    { "_id": "...", "Email": "user1@example.com", "role": "user" },
    { "_id": "...", "Email": "admin@example.com", "role": "admin" }
  ]
}
Responses
200
Array of all users (passwords excluded)
401
Not authenticated
403
Authenticated but not admin
